# ADR-001：模型运行时兼容性基线

- 状态：已采纳
- 日期：2026-08-02

## 决策

当前 Runtime 使用 `CoordinatorRouter`、`IntentResolver` 和 `CoordinatorConversationResponder` 分别作为模型领域路由、动作理解和总 Agent 自然语言回复的边界。默认确定性实现和 `PresetCoordinatorConversationResponder` 保持本地 Demo 可运行；启用 Maven Profile `model-openai` 和 Spring Profile `model-openai` 后，对应适配器使用 Spring AI `ChatModel` 调用 OpenAI-compatible 服务。`model-minimax` 使用 MiniMax Anthropic 兼容接口完成同样的三类调用。

总 Agent 普通对话会向模型提供代码预设的身份与回复约束、公开领域能力、待澄清候选和最近 12 条有效消息。路由和意图模型输出仍只能引用已注册 Agent、动作 code 与候选参数。Runtime 负责动作存在性校验、必填字段收集、访客归属、确认版本、幂等键和任务状态转换，模型不可直接执行领域动作。

## 已验证事实

1. 基线为 JDK 21、Spring Boot 3.5.14、Spring AI 1.1.2。
2. Spring AI Alibaba 使用 `1.1.2.2`，根 POM 同时导入 `spring-ai-alibaba-bom` 和 `spring-ai-alibaba-extensions-bom`。`agent-runtime` 已引入 Graph Core 和 Agent Framework。
3. Maven Profile `model-openai` 与 `model-dashscope` 分别引入对应 Starter。两个 Spring Profile 默认设置 `spring.ai.model.chat=none`，未配置密钥时不会创建外部 `ChatModel`，应用仍可启动并保持健康；真实调用必须显式设置 `AGENT_CHAT_MODEL_PROVIDER` 和对应密钥。
4. 模型调用异常、空对话回复、非 JSON 路由输出、未注册动作 code 或非法 input 都安全回退，不把模型原始错误暴露给访客。
5. 总 Agent 的 `message.final` 通过 `generationSource` 区分 `MODEL` 与 `PRESET_FALLBACK`，模型未配置或调用失败时不伪装为模型生成。
6. `SpringAiAlibabaCompatibilityTest` 使用本地 `ChatModel` stub 验证了 Graph Flux、`RunnableConfig.threadId`、`MemorySaver` checkpoint、ReactAgent 非流式/流式调用、真实 Tool 回调和 `outputType` 结构化输出，不依赖网络或真实密钥。结构化动作 code 只能映射到调用方提供的 `ActionDescriptor` 白名单。
7. 模型可见 Tool 仅允许 `QUERY`、`DRAFT`；`COMMIT`、`PAYMENT`、`AFTER_SALE` 由确定性策略拒绝，后续必须复用 Runtime 的任务与确认门禁。
8. 默认、OpenAI 和 DashScope 三种可执行包均已完成真实启动，`/actuator/health` 返回 `UP`；对应限定模块构建均成功。

## 依赖收敛

SAA Graph Core 1.1.2.2 声明了没有被其字节码引用的 MCP 聚合依赖 0.14.0，已在 `agent-runtime` 排除，保留 Spring AI 1.1.2 使用的 MCP JSON SDK 0.17.0。JetBrains annotations 统一由根 dependency management 管理为 24.0.1。Maven Enforcer `dependencyConvergence` 已对全部模块通过，依赖树不再包含 MCP 0.14.0。

兼容性测试仍使用 `MemorySaver`，但 M1 已增加 `DurableGraphCheckpointSaver`：RuntimeStore 保存可恢复 checkpoint，`graph-checkpoint-redis` Profile 可用时再以 Redis 加速；Redis 失败会回退到持久化事实。临时 MySQL 8.4 已完成 V001-V004 迁移及重启后会话读取，真实 Redis Profile 也已验证可连接并健康启动；这些环境验证不等同于真实模型供应商调用、超时和重试的生产验收。

## 后续条件

真实服务配置下的模型调用、超时、重试和健康验证仍应使用部署环境 Secret，不在仓库保存密钥；不得从 M1 的本地模型 stub 和中间件验证推断具体供应商已经生产验收。
