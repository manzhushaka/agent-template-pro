# 领域模块开发指南

每个新业务以独立模块实现 `DomainModule`，并注册明确的 `AgentAction`。动作只接收已经结构化的 `Map`/DTO 参数；模型输出、前端字段和外部 REST 报文都不能直接进入领域执行逻辑。

1. 为动作分配稳定代码，例如 `travel.schedule.query`。
2. 使用 `ActionDescriptor` 声明模式、必填字段和确认标题。
3. `QUERY`、`DRAFT` 可以直执；`COMMIT`、`PAYMENT`、`AFTER_SALE` 会被 Runtime 强制创建任务并等待确认。
4. 在 `execute` 内完成资格、状态和幂等校验，并通过适配器调用外部事实源。
5. 返回 `ActionResult`，其中卡片只包含可展示的脱敏数据。超时写操作必须返回结果未知并查单，不能直接重试。

生产模块还必须提供输入 DTO 校验、JSON Schema、外部调用审计、回调验签与 `RuntimeStore` 的持久化实现。
